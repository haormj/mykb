# Spec Delta

## MODIFIED Requirements

### Requirement: 统一对外接口
系统 SHALL 对外暴露稳定的知识检索接口，外部消费者不感知底层检索后端（如 WeKnora、codegraph）的具体实现。无论后端以何种文档标识命中，系统 SHALL 在返回前统一归一化为平台的知识概念标识。

#### Scenario: 通过统一接口检索
- **WHEN** 外部消费者发起知识检索请求
- **THEN** 系统通过统一接口返回结果，调用方无需指定或感知底层后端

#### Scenario: 命中归一化为概念标识
- **WHEN** 底层后端以自身文档 ID 返回命中
- **THEN** 系统把命中还原为平台知识概念标识后再返回，调用方看到的标识与后端无关

### Requirement: 按知识库隔离检索
系统 SHALL 在检索与问答请求中限定目标知识库，并只在该库当前 active 快照内检索，不跨库混检。

#### Scenario: 指定库检索
- **WHEN** 请求指定某个知识库发起检索
- **THEN** 系统只在该库 active 快照内检索并返回结果

#### Scenario: 不返回他库内容
- **WHEN** 请求指定知识库 A 发起检索
- **THEN** 结果不包含知识库 B 的内容

### Requirement: 多引擎适配
系统 SHALL 在统一接口之下支持多个可替换的检索后端。快照的版本、指针、映射与保留 SHALL 由平台编排层统一管理；后端 SHALL 仅实现快照物化、快照内检索、就绪轮询与快照删除，并声明能力与提供健康检查。新增后端时 SHALL 只需新增适配器，不改变外部接口或编排逻辑。

#### Scenario: 替换检索引擎
- **WHEN** 将某 markdown RAG 后端替换为另一实现（如从 WeKnora 换成 OpenViking）
- **THEN** 统一接口的外部行为保持不变，同一评测集可在不同后端上重跑对比

#### Scenario: 后端能力不支持
- **WHEN** 请求的检索类型（如代码检索）当前后端未声明支持
- **THEN** 系统返回明确的不支持错误，而不是静默返回空结果

## ADDED Requirements

### Requirement: 发布生成版本快照
系统 SHALL 在每次发布时把该库当前 knowledge 层级中 verified 且 stable 的概念全量物化为一个新的后端快照，并将其与该库发布时刻的 git commit 绑定；同一知识库的同一 git commit SHALL 不重复物化。

#### Scenario: 每次发布产生新快照
- **WHEN** 管理员对某知识库触发发布
- **THEN** 系统将该库当前已审核概念物化为一个新的后端快照，并记录对应的 git commit

#### Scenario: 同一 commit 复用
- **WHEN** 对已在某 git commit 发布过的知识库再次发布且内容未变
- **THEN** 系统复用该 commit 的既有快照，不重复物化

### Requirement: 发布为异步任务且全有或全无
系统 SHALL 以异步任务执行发布，同一知识库同一时刻至多一个发布任务。发布期间检索 SHALL 继续服务该库上一个已就绪快照。仅当全部文档就绪时系统 SHALL 原子切换到新快照；任一文档失败时整次发布失败，系统 SHALL 保留原 active 快照不变并清理未完成的新快照。

#### Scenario: 发布期间服务旧版本
- **WHEN** 一次发布正在进行且该库已有 active 快照
- **THEN** 检索仍基于旧 active 快照返回结果

#### Scenario: 存在失败文档
- **WHEN** 新快照的任一文档未成功就绪
- **THEN** 本次发布标记为失败，active 指针保持不变，系统清理未完成的新快照

#### Scenario: 并发发布被拒绝
- **WHEN** 该库已有发布任务在进行中又收到新的发布请求
- **THEN** 系统拒绝新请求并提示已有发布在进行

### Requirement: 概念与后端文档映射
系统 SHALL 在发布时把每条业务知识概念映射为后端的一条文档，并持久化概念标识与后端文档标识的对应关系。检索命中 SHALL 依据该快照的映射还原为概念标识，无法映射的命中 SHALL 被丢弃。

#### Scenario: 命中还原为概念
- **WHEN** 后端返回某条文档命中
- **THEN** 系统依据该快照的映射把命中还原为对应概念标识

#### Scenario: 无法映射的命中
- **WHEN** 后端返回的命中在映射中不存在
- **THEN** 系统丢弃该命中，不返回无法归因的结果

### Requirement: 快照保留与回滚
系统 SHALL 保留每个知识库最近若干版已就绪快照。保留窗口内的回滚 SHALL 通过切换 active 指针完成且无需重新物化；超出保留窗口的历史版本 SHALL 能由其 git commit 重新发布得到。

#### Scenario: 窗口内回滚
- **WHEN** 管理员回滚到仍在保留窗口内的历史版本
- **THEN** 系统把该库 active 指针切到该版本快照，检索立即返回该版本内容

#### Scenario: 超出窗口回滚
- **WHEN** 目标历史版本已不在保留窗口内
- **THEN** 系统由该版本对应的 git commit 重新物化一个快照后再切换

### Requirement: 检索不触发发布
系统 SHALL 保证检索与问答的读路径不触发任何后端发布或索引物化。发布 SHALL 仅由显式发布操作产生。

#### Scenario: 首次检索不发布
- **WHEN** 用户对某库发起首次检索且该库从未发布过
- **THEN** 系统按未发布处理返回结果，且不创建任何后端快照
